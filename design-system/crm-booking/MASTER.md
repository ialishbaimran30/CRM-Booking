## 1. Design principles

1. **Clarity over decoration.** This is a data-dense operational tool used all day. Every visual choice serves scanning, comparison, and action.
2. **One consistent language.** Neumorphic soft-UI, applied the same way everywhere. No screen should look like it came from a different app (Team Management currently does).
3. **Accessible by default.** WCAG 2.1 AA is the floor, not a nice-to-have — contrast, focus, keyboard, labels.
4. **Predictable.** Same control looks and behaves the same on every screen. Status colors mean the same thing everywhere.
5. **Responsive down to 360px.** Staff use tablets and phones; the client portal is mostly mobile.

## 2. Visual style

- **Aesthetic:** Neumorphic / soft-UI on a light blue-grey ground. Dual light/dark shadows for raised surfaces; inset shadows for wells (inputs, pressed states).
- **Keep:** the palette, the rounded corners, the soft shadows — they are coherent and on-brand for a calm operational tool.
- **Fix:** neumorphism's classic weaknesses — low contrast, invisible focus, ambiguous affordance. Every interactive element must have a **visible border or shadow state** and a **visible focus ring**.
- **Elevation scale (standardize the shadow strings into tokens — they are copy-pasted ad hoc today):**
  - `--elev-0` flat: no shadow
  - `--elev-raised`: `8px 8px 16px #d0d9e8, -8px -8px 16px #ffffff` (cards)
  - `--elev-sm`: `4px 4px 8px #d0d9e8, -4px -4px 8px #ffffff` (buttons, small tiles)
  - `--elev-inset`: `inset 4px 4px 8px #d0d9e8, inset -4px -4px 8px #ffffff` (inputs, toggles)
  - `--elev-overlay`: `0 12px 32px rgba(30,42,58,0.18)` (modals, popovers — a real drop shadow, not neumorphic, so they read as floating above)

```
--color-bg, --color-surface, --color-surface-sunken

--color-status-paid / -unpaid / -refunded / -overdue
--color-success/-warning/-danger + matching -bg (15% tint) + -fg (AA-compliant text)
```

### 3.3 Status color contract (must be identical everywhere — 3 conflicting versions exist today)

| Status | Meaning | Fill | Text |
|---|---|---|---|
| Pending / Waiting | awaiting action | `warning` @ 15% | darkened warning, AA on tint |
| Confirmed | booked, upcoming | `primary` @ 15% | `primary` (verify AA) |
| Completed / Paid | done, settled | `success` @ 15% | darkened success |
| Cancelled / Refunded | reversed | `danger` @ 15% | darkened danger |
| Overdue | needs escalation | `danger` solid + icon | inverse |

Status must **never be conveyed by color alone** — always pair with the text label (badges already do this; charts do not).

### 3.4 Dark mode

Not implemented and **not in scope** unless requested. If added later: define every token under `:root` first, override under `@media (prefers-color-scheme: dark)` and `[data-theme]`. Do not ship a partial dark mode.

## 4. Typography

- **Family:** Inter, with a real fallback stack: `'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, Helvetica, Arial, sans-serif`. **Inter must actually be loaded** (self-hosted `@font-face` or Google Fonts `<link>`); today it is named but never loaded, so the app renders in Times/system serif on most machines.
- **Base:** 16px / line-height 1.5 on body. Never set body text below 14px; 12px is reserved for labels/badges/captions only.
- **Scale (rem, 16px root):**

| Role | Size | Weight | Line-height |
|---|---|---|---|
| Display / page `h1` | 1.75 (28px) | 800 | 1.2 |
| Section `h2` | 1.375 (22px) | 700 | 1.3 |
| Card title `h3` | 1.0625 (17px) | 700 | 1.4 |
| Body | 1.0 (16px) | 400/500 | 1.5 |
| Body-sm (table cells, dense UI) | 0.875 (14px) | 400/500 | 1.45 |
| Label / caption / badge | 0.75 (12px) | 600, uppercase, `tracking-wide` | 1.3 |

- Uppercase + letter-spacing only for short labels, never for sentences.
- Numeric columns (amounts, counts): `font-variant-numeric: tabular-nums`.

## 5. Spacing & layout

- **Spacing scale (4px base, dashboard density):** `2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64`. Expose as `--space-1..--space-11`. Replace inline `style={{ padding: '32px' }}` / arbitrary margins with these.
- **Page shell:** fixed sidebar (240px desktop) + fluid main. Main content padding: 32px desktop / 24px tablet / 16px mobile. Content max-width 1200–1440px for reading comfort; tables may go full-bleed.
- **Grid:** 12-col fluid; card grids use `repeat(auto-fit, minmax(240px, 1fr))`.
- **Breakpoints (Tailwind defaults, mobile-first):** `sm 640 · md 768 · lg 1024 · xl 1280`. **Sidebar collapses to an off-canvas drawer below `lg`.**
- **Radii:** `--radius-sm 8px` (inputs, small buttons), `--radius-md 12px` (buttons, wells), `--radius-lg 16px` (cards), `--radius-xl 20px` (modals), `--radius-pill 9999px` (badges, avatars).

## 6. Component patterns

### Buttons
- Variants: **primary** (solid `primary`, white text), **secondary** (surface + `--elev-sm`, `primary` text), **ghost** (transparent, `primary` text), **destructive** (solid `danger` or `danger`-tint), **icon** (square, must have `aria-label` + tooltip).
- Sizes: sm 32px / md 40px / lg 48px min height. **Touch target ≥ 44×44px** on mobile (pad the hit area even if the visual is smaller).
- Every button: visible `:focus-visible` ring, `:hover` shadow/color shift, `:active` inset, `:disabled` 50% + `not-allowed`, and a **loading state** (spinner + "Saving…") that also disables. Never a 0ms state change — 150ms transition.
- One canonical `<Button>` component. Today buttons are re-implemented ~8 different ways (Tailwind classes, `.neu-btn` CSS, inline `style`, Bootstrap colors in Team Management).

### Forms
- One canonical `<FormField>` (the current `common/FormField.js` is **malformed — duplicated export**; fix before building on it).
- **Every field has a visible `<label>`** (not placeholder-as-label), programmatically associated (`htmlFor`/`id`). Placeholder is a hint, not a name.
- Inline validation: error message directly below the field, `danger` text + `aria-describedby` + red field border; never only a toast, never only a top-of-form summary.
- Required fields marked with text ("Required") or a legend, not just `*`.
- Inputs: sunken well style (`--elev-inset`), `--radius-sm`, 44px min height, 16px text (prevents iOS zoom), visible focus ring.
- Selects with many options (client picker, user picker) → use a searchable combobox, not a native `<select size>` list.

### Tables
- One canonical `<DataTable>` built on `@tanstack/react-table` (already a dependency, currently only partially used).
- Sticky header; zebra or row-hover (not both); right-align numeric columns with tabular figures; column min-widths.
- **Responsive:** horizontal scroll inside an `overflow-x:auto` wrapper **with a visible affordance**, or a stacked card layout below `md`. The page must never scroll horizontally as a whole.
- Row actions: max 2 inline buttons + overflow menu; never 3–4 raw buttons per row (Clients/Payments do this today).
- States: loading (skeleton rows), empty (illustration + primary CTA), error (retry).

### Cards
- `surface` bg, `--radius-lg`, `--elev-raised`, padding `--space-6` (24px). Optional header (`h3` + optional action), body, optional footer.
- Interactive cards: `--elev-sm` on hover, pointer cursor, and must be keyboard-activ​able (`role="button"` + `tabindex="0"` + Enter/Space, or wrap a real `<button>`/`<a>`). NotificationHistory cards are click-only today.

### Navigation (sidebar + topbar)
- Sidebar: brand, grouped nav links, active state = solid `primary` pill (keep). Max ~8 items per group; group Admin-only items under a divider/label.
- **Mobile: hamburger in the topbar opens the sidebar as an off-canvas drawer with a scrim; focus-trap it; close on route change / Esc / scrim tap.** No mobile nav exists today.
- Icons: **real SVG icons from `react-icons` (Feather/`fi` set recommended)**, 20px, `currentColor`. **Remove all emoji icons** (`📊 👥 📅 🛡️ 🔔 ⚙️ 🚪 🔒 ✏️ 🗑️ ➕ ✅ ❌`).
- Topbar: page context left, notification bell + profile menu right. Bell and avatar are icon buttons → need `aria-label`, `aria-expanded`, `aria-haspopup`, and keyboard open/close + focus management.
- Detail pages (Client Detail) get a back link **and** ideally a breadcrumb.

### Modals / dialogs
- Consolidate on **one** system. Recommendation: a single in-house `<Modal>` (accessible: `role="dialog"` `aria-modal`, focus trap, Esc to close, scrim click to close, return focus to trigger, body scroll lock). Use `sweetalert2` only for simple confirm() replacements, or drop it. Do not mix `sweetalert2` + hand-rolled modals + `window.confirm`.
- `window.confirm` for destructive actions (delete client/booking) → replace with the themed confirm dialog.
- Overlay: `rgba(30,42,58,0.4)` scrim (standardize — variants: `/40`, `black/40`, `bg-transparent pointer-events-none` all exist today). Modal card: `surface`, `--radius-xl`, `--elev-overlay`, `max-height:90vh`, internal scroll, responsive `width: min(92vw, 32rem)`.

### Notifications / toasts
- `react-hot-toast`, top-right, 4s, max 3 stacked. Success/error/loading variants themed to semantic tokens. One toast per action outcome (booking create already fires 2–3 — batch into one).
- Toaster must respect `prefers-reduced-motion`.

### Feedback states (define one component each, used everywhere)
- **Loading:** page = centered spinner + label; sections = skeletons matching final layout (reserve space, CLS < 0.1); buttons = inline spinner. Replace the ~10 bespoke `"Loading …"` text divs.
- **Empty:** icon + one-line explanation + primary CTA ("No clients yet — Add your first client"). Today: bare grey "No X found." centered text.
- **Error:** icon + plain-language message + Retry button. Today: red text or toast only.
- **Success:** toast for transient; inline confirmation for in-context (e.g. "Saved" on a field).

## 7. Iconography

- Library: `react-icons` `fi` (Feather) — outline, 1.5px stroke, 20px default / 16px dense / 24px touch.
- Color: `currentColor`. Never emoji. Never icon-only without `aria-label`.
- One icon per concept, mapped centrally (e.g. `dashboard→FiGrid`, `clients→FiUsers`, `bookings→FiCalendar`, `slots→FiClock`, `waitlist→FiList`, `payments→FiCreditCard`, `reports→FiBarChart2`, `team→FiShield`, `activity→FiActivity`, `notifications→FiBell`, `settings→FiSettings`, `logout→FiLogOut`, `delete→FiTrash2`, `edit→FiEdit2`, `add→FiPlus`).

## 8. Motion

- Durations: 150ms (hover/press/toggle), 200–250ms (dropdowns, toasts), 300ms (modal/drawer). Easing: `cubic-bezier(0.4, 0, 0.2, 1)` standard; `cubic-bezier(0, 0, 0.2, 1)` on enter; exits ~1.5× faster than enters.
- Motion must convey meaning (origin, continuity, hierarchy) — no purely decorative animation.
- **`@media (prefers-reduced-motion: reduce)`** — drop transforms/opacity transitions to near-instant (1ms), keep essential feedback. Add a global rule now; none exists.
- Animate `transform` / `opacity` only, never `width`/`height`/`top`/`left`.
- `framer-motion` is available if richer choreography is wanted (drawer, list reordering); otherwise CSS transitions are enough — don't add motion for its own sake.

## 9. Accessibility checklist (AA floor)

- Contrast ≥ 4.5:1 body text, ≥ 3:1 large text (≥ 24px or ≥ 19px bold) and UI component boundaries/icons.
- Every interactive element reachable and operable by keyboard; logical tab order; **visible `:focus-visible` ring on everything** (neumorphic `outline:none` without a replacement is the #1 risk here).
- Icon-only buttons: `aria-label`. Toggle buttons: `aria-expanded` / `aria-pressed`. Dialogs: `role="dialog"` + `aria-modal` + focus trap + restore focus.
- Forms: associated `<label>`, `aria-describedby` for errors/help, `aria-invalid` on error, error text not color-only.
- Images/avatars: meaningful `alt` or `alt=""` if decorative.
- Respect `prefers-reduced-motion`.
- `<html lang>` set (ok), page `<title>` per route (currently static "React App"), headings in order (no skipped levels).
- Live regions: `aria-live="polite"` for async results (toasts, "X on waitlist").

## 10. Responsive rules

- Mobile-first. Test at 360 / 768 / 1024 / 1440.
- No horizontal page scroll at any width. Wide content scrolls inside its own container.
- Sidebar → off-canvas drawer below `lg`.
- Tables → horizontal scroll wrapper or stacked cards below `md`.
- Modals → `width: min(92vw, …)`, full-height sheet style acceptable on mobile.
- Filter/search bars → wrap to column below `sm` (most already do).
- Tap targets ≥ 44px; ≥ 8px between adjacent targets (row action buttons are too tight today).
- Never disable zoom (viewport meta is currently fine — keep it).

## 11. Anti-patterns to remove (from `ui-ux-pro-max` guidance + this codebase)

- Emoji as UI icons.
- `outline: none` / removed focus rings with no replacement.
- Raw hex literals in components instead of tokens; three different shadow strings for "a card".
- Placeholder used as the only label.
- Errors surfaced only via toast or only at top of form.
- Inline `style={{}}` objects for layout that Tailwind/tokens should own (Bookings, Team Management, Dashboard, most detail pages).
- A second, unrelated visual language on one screen (Team Management = Bootstrap/Arial).
- `window.confirm` for destructive actions in a designed app.
- Multiple overlapping systems for the same job (modals: sweetalert2 + custom + confirm; two spacing systems; two `FormField` definitions).
- 1-second `setInterval` polling on four screens (battery/CPU cost, and jank) — prefer the existing WebSocket or the `storage` event alone, or back off to 5–10s.
- Dummy/test data injected into a production UI (Team Management dummy users).
- Decorative-only animation; animating layout properties; no reduced-motion path.
